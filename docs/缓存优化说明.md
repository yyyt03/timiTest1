# 缓存优化说明

## 问题描述

在开发环境中，每次进入英雄列表页面时，控制台都会输出：
```
英雄数据缓存已清除
使用本地英雄数据
英雄数据缓存已更新
```

这导致用户体验不佳，且每次都需要重新处理数据。

## 问题原因

1. **强制清除缓存**：每次页面加载都执行 `heroCache.clearCache()`
2. **开发环境热重载**：开发工具的热重载机制导致频繁重新加载
3. **缺乏环境区分**：没有区分开发环境和生产环境的配置
4. **缺乏数据变化检测**：无法检测英雄数据是否发生变化

## 优化方案

### 1. 智能缓存检查
- 移除强制清除缓存的逻辑
- 添加智能缓存检查，只在必要时清除缓存
- 缓存有效期：开发环境5分钟，生产环境30分钟

### 2. 环境配置管理
- 创建 `config.ts` 统一管理环境配置
- **开发环境 (develop)**：启用日志，短缓存时间，支持热重载，性能监控
- **体验版 (trial)**：使用生产环境配置，禁用开发特性
- **线上版 (release)**：专门的线上配置，最长缓存时间，启用错误上报和数据分析

### 3. 日志系统优化
- 使用统一的日志输出函数
- 开发环境显示详细日志
- 生产环境静默运行

### 4. 🆕 数据版本检查机制
- **智能版本检测**：基于数据内容生成哈希值
- **自动刷新**：当英雄数据发生变化时自动刷新缓存
- **性能优化**：避免频繁检查，设置合理的检查间隔
- **数据一致性**：确保用户始终看到最新数据

## 版本检查机制详解

### 工作原理
1. **数据哈希生成**：基于英雄总数、分类数量等关键字段生成哈希值
2. **版本对比**：每次检查时对比当前哈希值与缓存中的哈希值
3. **智能刷新**：哈希值不同时自动清除缓存并获取新数据
4. **检查间隔**：开发环境2分钟检查一次，生产环境5分钟检查一次

### 触发条件
- ✅ 缓存不存在
- ✅ 缓存已过期（时间检查）
- ✅ 数据版本已变化（版本检查）
- ❌ 缓存有效且版本相同

## 修改文件

1. `miniprogram/utils/config.ts` - 新增环境配置管理和版本检查配置
2. `miniprogram/utils/heroCache.ts` - 优化缓存逻辑、日志和版本检查
3. `miniprogram/pages/heroCategory/heroCategory.ts` - 智能缓存检查和版本检查
4. `docs/缓存优化说明.md` - 详细说明文档

## 预期效果

### 开发环境
- 首次加载：清除缓存，显示"缓存已过期或不存在，清除旧缓存"
- 5分钟内再次访问：显示"缓存有效，保留现有缓存"
- 数据变化时：自动检测并显示"数据版本已变化，清除旧缓存"
- 控制台输出：保留必要的调试信息

### 生产环境（体验版）
- 首次加载：清除缓存
- 30分钟内再次访问：使用缓存，无日志输出
- 数据变化时：自动检测并刷新，确保数据最新
- 用户体验：流畅，无延迟，数据始终最新

## 测试流程

1. **开发环境测试**：
   - 进入英雄列表页面
   - 观察控制台输出（应该减少）
   - 5分钟内再次进入，验证缓存保留
   - 修改英雄数据，验证自动刷新

2. **生产环境测试**：
   - 上传体验版
   - 测试缓存机制
   - 验证无多余日志输出
   - 测试数据变化时的自动刷新

## 注意事项

- 缓存时间可根据实际需求调整
- 生产环境建议禁用详细日志
- 版本检查间隔可根据数据更新频率调整
- 定期清理过期缓存数据
- 数据哈希算法可根据需要优化
